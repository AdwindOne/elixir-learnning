## 1. 基础与数据类型

### **Q: `=` 在 Elixir 中是什么意思？**
**A:** 它是**匹配操作符 (match operator)**，不是赋值操作符。它尝试将左边的模式（pattern）与右边的值进行匹配。只有当左边的变量未绑定时，它的行为才类似于赋值。这个概念是 Elixir 的基石。

### **Q: 列表 (List) 和元组 (Tuple) 有什么核心区别？应该如何选择？**
**A:**
- **列表 (List)**:
    - **实现**: 链表。
    - **性能**: 头部插入/读取快 (O(1))；获取长度/随机访问慢 (O(n))。
    - **用途**: 用于存储长度可变的元素集合，尤其适合递归处理（如 `[head | tail]`）。
- **元组 (Tuple)**:
    - **实现**: 内存中连续存储。
    - **性能**: 获取长度/通过索引访问快 (O(1))；更新慢（需要创建新元组）。
    - **用途**: 用于存储固定数量的元素，常用于函数返回多个值，如 `{:ok, result}` 或 `{:error, reason}`。

### **Q: 关键字列表 (Keyword List) 和图 (Map) 有什么区别？**
**A:**
- **关键字列表**:
    - **结构**: `[{:key1, "v1"}, {:key2, "v2"}]`
    - **特点**: 键必须是原子，键可重复，保留顺序。
    - **用途**: 主要用于函数的可选参数 (options)。这是 Elixir 的惯例。
- **图 (Map)**:
    - **结构**: `%{key1 => "v1", "key2" => "v2"}`
    - **特点**: 键可以是任何类型，键唯一，性能高。
    - **用途**: Elixir 中首选的键值存储结构。适用于绝大多数场景。

## 2. 函数与模块

### **Q: `and`/`or` 和 `&&`/`||` 有什么区别？**
**A:**
- `and`/`or`: **严格布尔运算符**。要求第一个参数必须是 `true` 或 `false`，否则报错。
- `&&`/`||`: **短路运算符**。可接受任何值，并根据 "truthiness"（`false` 和 `nil` 为假，其余为真）来判断。在开发中更常用。

### **Q: `if`, `cond`, `case` 之间如何选择？**
**A:**
- `if`: 用于简单的二元条件。
- `cond`: 用于检查多个**不相关**的条件，类似 `else-if` 链。
- `case`: 基于**同一个值**进行**模式匹配**。在 Elixir 中，由于模式匹配的强大，`case` 的使用频率远高于 `cond`。**优先考虑 `case`**。

### **Q: 管道操作符 `|>` 的工作原理是什么？**
**A:** 它将左边表达式的结果，作为右边函数调用的**第一个参数**。`x |> fun(y)` 等价于 `fun(x, y)`。它使得数据转换的流程像一条流水线，清晰易读。

## 3. 并发与 OTP

### **Q: Elixir 进程和操作系统的进程/线程有什么区别？**
**A:**
- **轻量级**: Elixir 进程由 BEAM 虚拟机管理，内存开销极小 (KB 级别)，可以轻松创建数十万个。
- **隔离性**: 进程间不共享内存，一个进程的崩溃不会影响其他进程。
- **通信**: 通过异步消息传递进行通信，而非共享内存，避免了锁和竞态条件。
- **调度**: BEAM 的抢占式调度器保证了系统的低延迟和高响应性。

### **Q: `GenServer.call` 和 `GenServer.cast` 有什么区别？**
**A:**
- **`call` (同步)**: 阻塞式。客户端等待服务器的回复。用于需要获取数据或确认操作完成的场景。触发 `handle_call/3` 回调。
- **`cast` (异步)**: 非阻塞式。客户端“发后不理”，不等待回复。用于执行不需要立即知道结果的后台任务或通知。触发 `handle_cast/2` 回调。

### **Q: 什么是监督树 (Supervision Tree)？常见的重启策略有哪些？**
**A:**
- **监督树**: 是由监督者和工作进程组成的层级结构，是 OTP 应用的骨架。它通过“让它崩溃”和自动重启的机制来构建容错系统。
- **重启策略**:
    - `:one_for_one`: (最常用) 只重启崩溃的那个子进程。
    - `:one_for_all`: 一个崩，全部（兄弟进程）都重启。
    - `:rest_for_one`: 重启崩溃的进程以及在它启动顺序之后的所有兄弟进程。

### **Q: 什么是背压 (Back-pressure)？**
**A:** 这是一个重要的概念。当一个进程（如生产者）产生消息的速度远快于另一个进程（消费者）处理消息的速度时，消费者的邮箱会无限增长，最终耗尽内存导致系统崩溃。OTP 本身不直接解决这个问题，需要开发者自己设计处理机制，例如：
- 使用 `GenServer.call` 进行同步调用，自然地限制了请求速度。
- 使用 `GenStage` 或 `Flow` 这种更高级的抽象，它们内置了背压机制。
- 在消费者过载时，主动丢弃消息或通知生产者暂停。

## 4. 高级主题与生态

### **Q: Behaviour 和 Protocol 有什么区别？**
**A:**
- **Behaviour (行为)**: 关注**模块**。它定义了一组 API 规范，要求不同模块以同样的方式行事。类似于接口。例如：`JsonParser` 和 `XmlParser` 都实现了 `Parser` 行为。
- **Protocol (协议)**: 关注**数据类型**。它实现了多态，允许同一个函数在不同数据类型上有不同的实现。例如：`Enum.count("hi")` 和 `Enum.count([1,2])` 都能工作，因为 `String` 和 `List` 都实现了 `Enumerable` 协议。

### **Q: 宏 (Macro) 和函数 (Function) 的核心区别是什么？**
**A:**
- **执行时机**: 宏在**编译时**执行，函数在**运行时**执行。
- **输入输出**: 宏接收和返回**抽象语法树 (AST)**，即代码本身。函数接收和返回值。
- **用途**: 宏可以“编写代码”，用于实现 DSL、修改语法结构等。应该极其谨慎地使用，因为它们会使代码更难理解和调试。**“能用函数就别用宏”** 是一个很好的原则。

### **Q: `Ecto.Repo.transaction/1` 能保证绝对的数据库原子性吗？在分布式环境下呢？**
**A:**
- 在**单个数据库节点**上，`Repo.transaction/1` 能利用数据库自身的事务机制保证其中的操作是原子性的（要么全部成功，要么全部回滚）。
- 在**分布式环境**下（例如，你需要在一个事务中调用外部 API），数据库事务**无法**保证外部操作的原子性。如果外部 API 调用失败，数据库操作可以回滚；但如果数据库操作失败，已经执行的外部 API 调用是**无法自动回滚**的。处理这种情况需要更复杂的模式，如 Saga 模式。

**最后的建议:** Elixir 的哲学是构建简单、明确、可容错的系统。在面试中，展现你对 OTP 核心思想（进程、消息、监督）的深刻理解，比背诵冷僻的语法细节要重要得多。
